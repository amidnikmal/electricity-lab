# Графическое тестирование (offscreen-съёмка как инструмент проверки)

Мы владеем приложением, поэтому можем рендерить сцену в PNG из командной строки и
**проверять визуальное поведение программно** — без скриншотов ОС и без GUI.
Это оказалось мощным диагностическим и регрессионным инструментом.

## Механизм
`current-lab --capture --demo <D> --view <electrical|mechanical|hydraulic> [--time T] [--layers ...] --out f.png`

- Скрытое GLFW-окно + FBO → `buildDemo` → `LiveSim` → `ProjectionBuilder` →
  `drawPrimitives` → `glReadPixels` → `stb_image_write`. UI-хром не рисуется.
- **`--time` — это СИМУЛИРОВАННЫЕ секунды** (гоним по `sim.time()` с фиксированным
  шагом). Не реальные: авто-слоумо иначе масштабирует время и даёт «замёрзшие» кадры.
- Реализация: `src/render/CaptureRenderer.*`, `src/app/CaptureConfig.h`, `src/main.cpp`.

## Техника: сравнение кадров
Главный приём — снять сцену в РАЗНЫХ состояниях и сравнить (md5 или глазами):

```
current-lab --capture --demo AcRectifier --view electrical --time 0.125 --out a.png
current-lab --capture --demo AcRectifier --view electrical --time 0.375 --out b.png
md5sum a.png b.png      # одинаковы → цепь замерла (баг); разные → колеблется (ок)
```

## Чем это поймали в сессии 2026-06-15 (реальные кейсы)
- **AC-демка «не работает».** Кадры на t=0.125 и t=0.375 оказались байт-в-байт
  идентичны → сим заморожен. Корень: `LiveSim` усыплял цепь с `AcVoltageSource`
  (settle). Починили → кадры стали разными → подтвердили колебание+выпрямление.
- **Баг самого механизма съёмки.** Идентичные кадры сохранялись даже после фикса AC —
  оказалось, `--time` считался в РЕАЛЬНЫХ секундах. Сравнение md5 это и вскрыло.
- **«Индуктор не связан с цепью».** Снимок механической аналогии показал маховик
  гладким диском без зубьев, цепь «втыкается» без зацепления. Это НЕ баг солвера
  (тесты RL зелёные) — чисто визуал. Починили (зубчатый обод) → снимок подтвердил.
- **Конденсатор-пружина зашкаливает.** Снимок RLC-механики «до» — пружина в максимуме;
  «после» (tanh-смягчение) — умеренная амплитуда, биения видны.

## Когда применять
- **Диагностика «странного» поведения**, которое не ловят числовые тесты (визуал, фазы,
  замерзание анимации).
- **Регрессия рендера**: эталонный PNG → сравнение после правок (порог по пикселям или md5
  для детерминированных сцен; в тестах есть `RenderHasNoHiddenState` — рендер детерминирован).
- **Генерация иллюстраций** для документации/пособий (см. `docs/lab-manual/`).

## Ограничения / на будущее
- Камера не авто-фитит границы цепи → схема занимает часть кадра, много пустого места.
  TODO: авто-fit под bbox примитивов для идеальных иллюстраций.
- Численные тесты (gtest, 566 шт.) остаются основным контролем; графическая съёмка их
  ДОПОЛНЯЕТ для того, что число не ловит.
- Тест-бинарь собирается БЕЗ GL — графические проверки гоняются через бинарь приложения
  (`current-lab`), не через `current-lab-tests`.
