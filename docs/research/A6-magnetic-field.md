## Как сейчас устроено в проекте (ШАГ 1)

### Модель магнитного поля

- Единственный файл: `src/physics/MagneticFieldModel.h` (83 строки). Никаких других
  файлов `*magnet*`, `*Bfield*`, `*Biot*`, `*Savart*`, `*Amper*`,
  `*Solenoid*`, `*LoopField*` в `src/physics/` нет.
- Формула: `B = kMu0 * |I| / (2 * kPi * r)` — закон Ампера для бесконечно
  длинного прямого провода (`magneticFieldMagnitude()`, строка 28–32).
- Константа `kMu0 = 4e-7 * kPi ≈ 1.2566·10⁻⁶ H/m` — вакуумная магнитная
  проницаемость (`src/physics/PhysicalUnits.h:10`). Хотя запись `4e-7 * kPi`
  зависит от порядка объявления `kPi` (строка 9), обе константы `constexpr` и
  определены в правильном порядке — компилируется корректно.
- Направление поля: `PageDirection::OutOfPage` (⊙) и `IntoPage` (⊗) —
  определяется правилом правой руки: `current * side >= 0 → OutOfPage`, иначе
  `IntoPage` (`MagneticFieldModel.h:64–68`). `side` = ±1 (над/под проводом в
  плоскости экрана).
- Сэмплирование: `sampleMagneticField()` (строки 34–81) генерирует глифы вдоль
  проводника-сегмента на ДВУХ фиксированных расстояниях от оси провода:
  `wireThickness * 0.75` и `wireThickness * 1.15` — всегда четыре глифа на точку
  (2 стороны × 2 радиуса). Шаг вдоль провода: `60.0 / cameraScale`, clamped
  `[16, 90]` пикселей (строки 49–51). Сегменты короче 1.0 world unit
  пропускаются (строка 43).
- Только проводники: магнитный слой не излучается для конденсаторов
  (`ProjectionBuilder.cpp:1967–1969`: `comp.type != ComponentType::Capacitor`),
  что разумно (DC-конденсатор не проводит постоянный ток).

### Визуализация

- Глифы: OutOfPage → залитый круг (⊙), IntoPage → крест (⊗) из двух диагональных
  линий (`ProjectionBuilder.cpp:654–661`). Цвет: голубой/синий, интенсивность
  пропорциональна нормированной магнитуде (`frac = B / B_max` по сегменту).
- Магнитный слой — `VisualizationLayer::MagneticField`, статус
  «qualitative quasi-static» (`VisualizationStatus.h:45–48`). Слой выключен во
  всех learner-пресетах; включён только в Debug (`VisualizationPresets.h:108`).
- Индуктор: отдельная функция `emitInductorPhysics()`
  (`ProjectionBuilder.cpp:414–427`) рисует «magnetic energy glow» — фиолетовое
  свечение-диск вокруг центра катушки с интенсивностью от |I|. Это HE
  физическое поле соленоида, а визуальный «энергетический ореол».
- Документация честно называет модель «qualitative» и «not a full 3D
  Biot-Savart integration» (`VISUALIZATION_MODEL.md:48–52`; `PHYSICS_VISUAL_LAYER_STATUS.md:16`).

## Находки (ШАГ 2 + ШАГ 3)

### [PHYSICS-BUG] Закон Ампера для бесконечного провода применён к конечным сегментам — завышение B у концов сегментов
**Severity: Medium**

- **Проект:** `src/physics/MagneticFieldModel.h:28–32` — `B = μ₀|I|/(2πr)`
  (формула бесконечного прямого провода); вызывается из `sampleMagneticField()`
  (строка 72) для каждого конечного сегмента между изгибами/узлами.
- **Реальность/источники:** для КОНЕЧНОГО прямого отрезка провода магнитное
  поле описывается законом Био–Савара: `B = (μ₀I/4πr)·(sin θ₁ + sin θ₂)`, где
  θ₁ и θ₂ — углы от точки наблюдения к концам сегмента. Для бесконечного
  провода sin θ₁ = sin θ₂ = 1 → B = μ₀I/(2πr). На конце полубесконечного
  провода sin θ₁ = 1, sin θ₂ = 0 → B = μ₀I/(4πr) — ровно ВДВОЕ МЕНЬШЕ.
  В середине длинного сегмента обе формулы сходятся. На коротких сегментах
  (изгибы, углы схемы) ошибка максимальна.
  https://en.wikipedia.org/wiki/Biot%E2%80%93Savart_law
  http://hyperphysics.phy-astr.gsu.edu/hbase/magnetic/magcur.html
- **Идеал:** заменить формулу на Био–Савара для конечного отрезка:
  `B = (μ₀I/4πr)·((a·u)/len_a + (b·u)/len_b)`, где `u` — единичный вектор
  вдоль провода, `a` и `b` — векторы от точки наблюдения к концам сегмента.
  Для длинных сегментов это совпадёт с текущей формулой; для коротких —
  даст физически корректное значение. Инфраструктура уже готова (Vec2,
  dot/cross/length), формула добавляется в 3 строки.

### [PHYSICS-BUG] Магнитное поле сэмплируется только на ДВУХ фиксированных радиусах у поверхности провода — спад 1/r не виден
**Severity: Medium**

- **Проект:** `src/physics/MagneticFieldModel.h:53–56` — радиусы
  `wireThickness * 0.75` и `wireThickness * 1.15`; `sampleMagneticField()`
  (строки 63–75) размещает глифы только на этих двух расстояниях.
  `magneticFieldMagnitude()` правильно вычисляет B = μ₀|I|/(2πr) с
  переданным радиусом — но радиус НЕ варьируется, поэтому юзер видит лишь
  два кольца глифов постоянной яркости.
- **Реальность/источники:** магнитное поле прямого провода спадает как ~1/r.
  Образовательные визуализации (PhET «Magnet and Compass», MIT TEAL
  Magnetostatics) показывают непрерывное поле на многих расстояниях — либо
  силовыми линиями (окружностями разной густоты), либо стрелками разной
  длины. Спад 1/r — ключевой обучающий факт: B ослабевает с расстоянием, в
  отличие от E провода (которое вообще не спадает в бесконечной 2D-модели).
  https://phet.colorado.edu/en/simulations/magnet-and-compass
  http://hyperphysics.phy-astr.gsu.edu/hbase/magnetic/magcur.html
- **Идеал:** добавить 3–5 радиусов (wireThickness × [0.75, 1.15, 1.8, 2.8, 4.5])
  с пропорционально меньшей альфой/размером глифа на больших радиусах.
  Либо (радикальнее) рисовать концентрические пунктирные окружности —
  «силовые линии» — с густотой ~1/r. Первый вариант (3 строки в конфиге
  радиусов) — быстрый и сразу покажет спад.

### [PHYSICS-BUG] Нет модели соленоида/петли — поле катушки индуктора показано как сумма полей отдельных зигзагообразных сегментов
**Severity: High**

- **Проект:** `src/projection/ProjectionBuilder.cpp:1967–1969` — магнитный слой
  вызывается для КАЖДОГО сегмента-проводника, включая сегменты, образующие
  зигзаг индуктора. `emitInductorPhysics()` (строка 414–427) рисует лишь
  фиолетовый «glow»-диск — не физическое поле. Никакого `SolenoidModel`,
  `LoopField` или интегрирования по виткам в коде нет.
- **Реальность/источники:** соленоид (катушка) создаёт ДИПОЛЬНОЕ поле:
  внутри — практически однородное `B = μ₀NI/l`, снаружи — спадающее поле,
  похожее на поле стержневого магнита. Одиночная петля: на оси
  `B = μ₀IR²/(2(x²+R²)^(3/2))`, в центре петли `B = μ₀I/(2R)`.
  Студент, глядя на поле зигзага из прямых проводов, НЕ увидит ни
  однородного поля внутри, ни дипольной структуры снаружи — а это главное
  физическое содержание катушки.
  https://en.wikipedia.org/wiki/Solenoid
  http://hyperphysics.phy-astr.gsu.edu/hbase/magnetic/solenoid.html
- **Идеал:** добавить `SolenoidModel` в `src/physics/`: по геометрии
  индуктора (центр, длина, ширина — уже известны из
  `inductorGeometry()` в `ProjectionBuilder.cpp`) вычислять поле на оси
  (аналитическая формула) и в плоскости (можно аппроксимировать диполем
  `B_dipole = (μ₀/4πr³)·(3(m·r̂)r̂ − m)` с магнитным моментом
  `m = N·I·A`). Для соленоида: `B_inside = uniform`, рендерить
  параллельные стрелки внутри. Это даст студенту КАЧЕСТВЕННО ВЕРНУЮ
  картину поля вместо физически бессмысленного зигзага.

### [DISCREPANCY] Термин «quasi-static» в документации неточен — модель чисто СТАТИЧЕСКАЯ (DC)
**Severity: Low**

- **Проект:** `src/visualization/VisualizationStatus.h:46` — badge
  «qualitative quasi-static»; аналогично `VISUALIZATION_MODEL.md:49–50`.
- **Реальность/источники:** «Квазистатический» (quasi-static) в
  электродинамике означает: поля меняются МЕДЛЕННО, так что током
  смещения можно пренебречь, но ИНДУКЦИЯ (закон Фарадея) ещё работает.
  В проекте нет закона Фарадея, нет индукции, нет изменяющегося B —
  формула B = μ₀I/(2πr) чисто магнитостатическая (DC). Термин
  «quasi-static» вводит в заблуждение — он намекает на наличие временной
  зависимости, которой нет.
  https://en.wikipedia.org/wiki/Amp%C3%A8re%27s_circuital_law
- **Идеал:** заменить «quasi-static» на «static DC» или «DC magnetostatic»
  в `VisualizationStatus.h:46` и `VISUALIZATION_MODEL.md:50`.

### [VISUAL-BUG] Глиф «Into page» (⊗) трудноразличим при маленьком размере
**Severity: Low**

- **Проект:** `src/projection/ProjectionBuilder.cpp:657–661` — крест из двух
  диагональных линий толщиной 1.5 px; глифы начинаются с `glyphR = 3.5`
  пикселей. При `frac ≈ 0` крест занимает ~3 px — практически неразличим
  на фоне внешнего круга.
- **Реальность/источники:** стандартное обозначение ⊗ (into page) использует
  жирный крест внутри круга; в образовательных визуализациях (PhET,
  Hyperphysics) направление часто кодируется ЦВЕТОМ (красный/синий)
  или формой стрелки, а не только ⊙/⊗.
- **Идеал:** увеличить минимальный `glyphR` до 5.0 или утолщить линии
  креста до 2.0 px при малых размерах. Как альтернатива — кодировать
  IntoPage тёплым цветом (розовый/красный), OutOfPage — холодным
  (голубой/синий), как в конвенции «красный — север/наружу».

### [IDEA] Нет визуализации суперпозиции полей от нескольких проводов
**Severity: Medium (идея/будущее)**

- **Проект:** `emitMagneticField()` вызывается для каждого сегмента
  независимо (`ProjectionBuilder.cpp:1967–1969`), глифы попадают в общий
  `ctx.out.circles`. Суперпозиция НЕЯВНАЯ — глифы разных проводов
  накладываются в экранном пространстве, но пользователь не видит
  результирующего вектора B.
- **Реальность/источники:** принцип суперпозиции — фундаментален для
  магнитостатики: `B_total = Σ B_i`. Демонстрация того, что между двумя
  параллельными проводами с встречными токами поле УСИЛИВАЕТСЯ (B
  складывается), а с сонаправленными — ОСЛАБЛЕВАЕТ (B вычитается, на
  средней линии B=0) — мощный педагогический приём.
  https://en.wikipedia.org/wiki/Superposition_principle
- **Идеал:** опциональный режим «Grid B»: наложить регулярную сетку
  (например, 40×30 точек) на область схемы, в каждой точке вычислить
  ΣB_i от всех сегментов по закону Био–Савара, и нарисовать либо
  стрелки (как E-field backdrop в `ProjectionBuilder.cpp:666`), либо
  тепловую карту |B|. Даст полную картину поля от всей цепи разом.

### [IDEA] Добавить грид-выборку B по закону Био–Савара как «продвинутый слой»
**Severity: Medium (идея/будущее)**

- **Проект:** вся инфраструктура для стрелочного/теплового поля УЖЕ есть —
  `emitFieldBackdrop()` (`ProjectionBuilder.cpp:666`) делает ровно это для
  E-поля: сетка источников (узлов), вычисление поля в каждой точке сетки,
  рендеринг стрелок. Магнитный аналог потребовал бы заменить скалярный
  потенциал на векторный (Biot–Savart сумма по всем токоведущим
  сегментам) — но структура `out.arrows`, `out.circles` та же.
- **Реальность/источники:** MIT TEAL 8.02, PhET «Faraday's Law»,
  Falstad Circuit Simulator — все показывают B либо сеткой стрелок, либо
  силовыми линиями.
  https://phet.colorado.edu/en/simulations/faradays-law
  https://en.wikipedia.org/wiki/Biot%E2%80%93Savart_law
- **Идеал:** функция `emitMagneticFieldBackdrop()` — для каждой точки
  регулярной сетки (20×15) вычислить `B = (μ₀/4π)·Σ( I_i · Δℓ_i × r̂_i / r_i² )`,
  отрисовать стрелками. При малом количестве сегментов (<50) и скромной
  сетке — реально в реальном времени (сейчас E-field backdrop уже
  работает, сложность та же).

### [PHYSICS-BUG] Отсечка сегментов короче 1.0 world unit скрывает поле на мелких деталях схемы
**Severity: Low**

- **Проект:** `src/physics/MagneticFieldModel.h:43` — `if (absI <= 1e-12 ||
  len <= 1.0) return samples;`. При сильном увеличении (zoom in)
  короткие сегменты (<1 wu) не излучают магнитное поле.
- **Реальность/источники:** порог, вероятно, защищает от вырожденной
  геометрии (нулевая длина), но 1.0 world unit — произвольная величина,
  не привязанная к физическому масштабу. При zoom in видимые сегменты
  короче 1.0 wu теряют B-поле.
- **Идеал:** заменить на `len <= kMinimumPhysicalLength` (1e-9, уже
  определена в `PhysicalUnits.h:8`) или на `len <= wireThickness * 0.1`
  для защиты только от реально вырожденных сегментов.

### [DISCREPANCY] Абсолютная величина B нормируется на максимум сегмента — информация об абсолютной силе поля теряется
**Severity: Low**

- **Проект:** `src/projection/ProjectionBuilder.cpp:638–644` —
  `maxMagnitude` вычисляется по всем сэмплам сегмента, затем каждый глиф
  получает `frac = B/maxMagnitude`. Глифы ВСЕГДА растянуты на полный
  диапазон яркости 0..1, независимо от абсолютного B.
- **Реальность/источники:** это осознанный педагогический выбор (доки:
  «qualitative»), но студент не может сравнить силу поля между разными
  токами (1 А vs 10 А) или разными цепями — всё выглядит одинаково ярко.
- **Идеал:** нормировать на ГЛОБАЛЬНЫЙ `maxMagnitude` по всей схеме (или
  на `μ₀I_max/(2π·wireThickness)`), чтобы глифы слабого поля были
  заметно тусклее/меньше. Либо добавить опциональный цветовой легенду
  «B, T» как для потенциала.

Собраны по источникам (Wikipedia, Hyperphysics, PhET, педагогическая

| Ошибка | Как в проекте |
| --- | --- |
| **Спад 1/r² вместо 1/r**: путают с законом Кулона для точечного заряда | Проект правильно использует 1/r ✓ |

## Сводка по severity

- **High: 1** — отсутствие модели соленоида/петли (катушка индуктора показывает физически неверную картину поля).
- **Medium: 4** — бесконечный провод для конечных сегментов (Biot–Savart); фиксированные радиусы (нет видимого спада 1/r); нет суперпозиции (grid B); грид-выборка Biot–Savart как идея.
- **Low: 4** — термин «quasi-static» в доках; плохая различимость ⊗; отсечка `len <= 1.0`; нормировка B на сегмент (нет сравнения силы поля между цепями).

Главный вывод: модель магнитного поля **корректна для того, что заявлено** — качественное DC-поле прямого провода по Амперу. Но для темы «магнитное поле» критически не хватает трёх вещей:
1. **Модели соленоида/петли** — студент не видит главного: поле катушки.
2. **Видимого спада 1/r** — расстояние до провода не варьируется.
3. **Суперпозиции** — нет синтеза полей от нескольких проводов в одной точке.
