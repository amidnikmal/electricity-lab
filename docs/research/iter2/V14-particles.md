# V14 — Состязательная перепроверка: частицы (B2)

**Дата:** 2026-06-14
**Источник находки:** docs/research/B2-particles.md (итерация 2)

## (1) LCG берёт младшие биты (`% 10000`) → короткий период/смещение в `pickOutgoing`

**Вердикт: ПОДТВЕРЖДЕНО**

**Доказательство:** `src/physics/ParticleSim.cpp:683-684`

```cpp
pickState = pickState * 1664525u + 1013904223u;
double roll = (pickState % 10000u) / 10000.0;
```

LCG с параметрами Борланда/NumRec (множитель 1664525, инкремент 1013904223) по модулю 2^32 (неявное переполнение `uint32_t`). Выделение `% 10000` берёт ~14 младших бит состояния. Для LCG по модулю степени двойки младшие k бит имеют период не более 2^k. При k ≈ 14 период ≤ 16384 — чрезвычайно короткий для режекторной выборки.

**Источник:** Knuth TAOCP §3.2.1.1, Theorem A — LCG с модулем 2^e: период младших k бит = 2^k (при полном периоде старших бит). Использование `% N` без сдвига вправо (деления на степень двойки) — классическая ошибка.

## (2) Радиус частиц не обновляется при движении слайдера толщины провода

**Вердикт: ПОДТВЕРЖДЕНО**

**Доказательство:**

- `MainWindow::updateParticleSim` (src/ui/MainWindow.cpp:284): вычисляет `particleRadius` из текущего `m_wireThickness`
- Вызов `sim.configure(specs, particleRadius)` (строка 308) — только при `!configured()`, т.е. при первой инициализации
- Вызов `sim.setTargets(specs)` (строка 310) — каждый кадр, НЕ принимает радиус

`ParticleSim::setTargets` (src/physics/ParticleSim.cpp:863-880):
```cpp
void ParticleSim::setTargets(const std::vector<ChannelSpec>& channels) {
    if (!m_impl->world) return;
    if (layoutSignature(channels) != m_impl->signature) {
        configure(channels, m_impl->particleRadius);  // ← СТАРЫЙ радиус!
        return;
    }
    // ... обновляет только targetSpeed и paddleSpeed
}
```

При совпадении сигнатуры (обычный случай при изменении толщины провода) обновляются только скорости. При изменении сигнатуры вызывается `configure` с СОХРАНЁННЫМ `m_impl->particleRadius` — старым значением, установленным при последнем `configure()`. Таким образом, `setTargets` _никогда_ не получает и не применяет новый радиус.

**Источник:** docs/HANDOFF.md — «известный баг радиуса». Пользователь двигает слайдер толщины → геометрия мира не перестраивается.

## (3) При нулевом токе частицы застревают в камерах узлов

**Вердикт: ПОДТВЕРЖДЕНО**

**Доказательство:** `src/physics/ParticleSim.cpp:465-467`

```cpp
const Channel& to = channels[targetChannel];
double speed = std::abs(to.spec.targetSpeed);
if (speed < 1e-9) return; // no flow — no push, water rests
```

`steerThroughChamber` (строка 442) вызывается для частиц, находящихся в зоне камеры узла (t < trimA или t > length - trimB, строка 548). При нулевом токе `targetSpeed ≈ 0`, условие `speed < 1e-9` истинно, функция возвращает без приложения направляющей силы. Частица получает только изотропные тепловые толчки (строка 527-538), не имея смещения в сторону выхода из камеры → эффективно застревает.
