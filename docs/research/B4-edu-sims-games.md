## PhET Circuit Construction Kit (DC)

[IDEA] Severity: HIGH

- **Проект:** current-lab
- **Реальность/источники:** https://phet.colorado.edu/en/simulations/circuit-construction-kit-dc
  - PhET CCK: drag-and-drop компоненты из палитры (батарейки, лампочки, резисторы, ключи, провода) прямо на холст.
  - Компоненты выглядят «как в жизни» (батарейка похожа на батарейку, лампочка на лампочку) — это снижает когнитивный барьер для новичков, не знающих схемных обозначений.
  - Лампочка светится пропорционально току/мощности — мгновенная визуальная обратная связь.
  - Короткое замыкание: анимация огня/искр — немедленная и запоминающаяся обратная связь об ошибке.
  - Электроны анимируются как движущиеся точки вдоль проводов (скорость ~ток).
  - Встроенные измерительные приборы: вольтметр, амперметр — перетаскиваются на схему, показывают реальные значения.
  - Режимы: schematic и «lifelike» — можно переключаться.
  - Основан на исследованиях: каждый сим проходит пользовательское тестирование со студентами, итеративно дорабатывается.
  - Исследования PhET показали: использование симов + традиционные лабы → улучшение понимания концепций (Wieman et al., Science 2008).
- **Идеал:**
  1. «Lifelike»-режим отрисовки компонентов (лампочка, батарейка) — как опциональный пресет, не заменяющий schematic.
  2. Визуальная обратная связь об ошибках: свечение/искры при КЗ, нагрев/цвет при перегрузке.
  3. Drag-and-drop из палитры компонентов на холст (сейчас редактирование через UI-панель).
  4. Измерительные щупы (вольтметр/амперметр), перетаскиваемые по схеме.

## PhET — дизайн-философия

[IDEA] Severity: HIGH

- **Проект:** current-lab
- **Реальность/источники:** https://en.wikipedia.org/wiki/PhET_Interactive_Simulations
  - Ключевые принципы PhET (из публикаций Wieman, Perkins, Adams):
    - «Make the invisible visible» — показывать электроны, поля, потенциал.
    - «Connect to real-world phenomena» — лампочка, батарейка, а не только абстрактные символы.
    - «Scientist-like exploration» — студент исследует, а не просто смотрит.
    - «Intuitive, game-like environment» — простота входа, отсутствие инструкций.
    - Итеративная разработка с тестированием на студентах.
    - Минимум текста, максимум визуального воздействия.
  - current-lab уже реализует «make the invisible visible» (потенциал, E-field, дрейф, surface charge, magnetic field) — это сильная сторона.
  - Не хватает: «game-like», «real-world connection».
- **Идеал:**
  1. Добавить «lifelike»-скин компонентов как опцию.
  2. Итеративное тестирование с реальными студентами (не только автотесты).
  3. Минимизировать текст в пользу визуализации там, где это возможно.

## Falstad Circuit Simulator

[IDEA] Severity: MEDIUM

- **Проект:** current-lab
- **Реальность/источники:** https://www.falstad.com/circuit/
  - Схематический симулятор: зелёный = положительное напряжение, красный = отрицательное, серый = земля.
  - Жёлтые движущиеся точки = ток (аналог электронов).
  - Огромная библиотека примеров схем (~200+ схем).
  - Правая кнопка → редактировать компонент.
  - Подсхемы (subcircuits) — можно вкладывать схемы друг в друга.
  - Более инженерный/технический, менее «игровой», чем PhET.
  - Написан Paul Falstad, позже портирован на JavaScript Iain Sharp.
- **Идеал:**
  1. Библиотека демо-схем «из коробки» — сейчас есть DemoCircuits.h, но нужна встроенная галерея.
  2. Иерархические подсхемы (subcircuits) — для продвинутых пользователей.

## Zachtronics: SHENZHEN I/O, TIS-100, KOHCTPYKTOP

[IDEA] Severity: HIGH

- **Проект:** current-lab
- **Реальность/источники:**
  - https://www.zachtronics.com — SHENZHEN I/O: «BUILD CIRCUITS. WRITE CODE. RTFM.» Игрок проектирует электронные схемы и пишет микрокод. Эстетика: даташиты, мануалы, тёмная тема, моноширинный шрифт.
  - https://en.wikipedia.org/wiki/Zachtronics — Флагманский приём: **гистограммы эффективности** после каждого решения. Игрок видит своё решение на фоне распределения решений других игроков по трём метрикам: стоимость, потребляемая мощность, занимаемая площадь. Это создаёт внутреннюю мотивацию к оптимизации БЕЗ баллов, очков, «уровней».
  - KOHCTPYKTOP: Engineer of the People (2009, бесплатная) — freeform проектирование кремниевых схем (размещение транзисторов, дорожек).
  - Zachademics (2019): все игры Zachtronics бесплатны для школ и образовательных НКО.
  - Opus Magnum, SpaceChem, Infinifactory — тот же паттерн: открытое решение + гистограммы.
- **Идеал:**
  1. **Гистограммы эффективности** в learning-панели: после решения задачи показывать, как решение пользователя сравнивается с другими (или с эталонным). Метрики: точность ответа, время, число попыток. Без очков и геймификации — чистые данные.
  2. **«Даташит»-эстетика** для инспектора: моноширинный шрифт, таблицы параметров как в справочнике (уже частично есть в InspectorPanel).
  3. **Режим открытой оптимизации**: задача «построй схему с заданным эквивалентным сопротивлением, используя минимум компонентов».

## Electric Box / Crazy Machines / Incredible Machine

[IDEA] Severity: MEDIUM

- **Проект:** current-lab
- **Реальность/источники:** (knowledge)
  - **Electric Box** (2009, Flash/мобильная): головоломка — соедини источник энергии с целью через цепь устройств (лазеры, вентиляторы, генераторы). Каждый уровень — готовая схема с недостающим звеном.
  - **Crazy Machines / The Incredible Machine**: построй машину Руба Голдберга из физических компонентов. Главный UX-принцип: **drag-and-drop из инвентаря, мгновенный запуск симуляции**, смотри что работает/ломается.
  - Обе игры используют **goal-oriented puzzles**: «зажги лампочку», «открой дверь». Это создаёт narrative engagement.
- **Идеал:**
  1. Режим «Circuit Puzzle»: дана частичная схема + цель («достигни тока 0.5 A через R1»), пользователь добавляет/меняет компоненты.
  2. Drag-and-drop из палитры компонентов (совпадает с идеей PhET).

## Minecraft Redstone / Turing Complete / NAND Game / Logic World

[IDEA] Severity: MEDIUM

- **Проект:** current-lab (отдалённо — digital logic не в скоупе, но педагогический паттерн полезен)
- **Реальность/источники:** (knowledge)
  - **Minecraft Redstone**: игроки изучают булеву логику и цифровые схемы непреднамеренно, через игру. Принцип: **learning by doing в песочнице**, мотивация — построить работающий механизм.
  - **Turing Complete** (игра): от NAND до полноценного компьютера. Каждый уровень вводит ровно одну новую концепцию и требует её применить.
  - **NAND Game** (бесплатный браузерный): та же идея. Минималистичный интерфейс.
- **Идеал:**
  1. **Scaffolded progression** в learning-модуле: каждый task вводит ровно одну новую концепцию (сейчас TaskGenerator делает randomised circuits — это хорошо, но последовательность могла бы быть выстроена явнее).
  2. Принцип «от одного компонента к сложной схеме» уже частично реализован через difficulty levels.

## Геймификация физики (обзор исследований)

[IDEA] Severity: MEDIUM

- **Проект:** current-lab
- **Реальность/источники:** (knowledge — synthesis of known research)
  - Мета-анализ Hamari et al. (2014): геймификация работает, когда есть осмысленная цель, а не просто очки/badges.
  - PhET избегает геймификации в классическом смысле — вместо этого делает «game-like» среду (интуитивную, с мгновенной обратной связью).
  - Zachtronics использует social comparison (гистограммы) вместо геймификации — это ближе к intrinsic motivation (Deci & Ryan, SDT).
  - **Predict-then-verify** (уже в current-lab, LEARNING_MODULE.md:18) — сильный педагогический приём: generation effect (Slamecka & Graf 1978).
  - **Attempt-first gating** (LEARNING_MODULE.md:30) — testing effect (Roediger & Karpicke 2006).
  - Что можно добавить: **немедленная визуальная обратная связь** при ошибках (PhET: пожар при КЗ), **социальное сравнение** (Zachtronics: гистограммы), **scaffolded progression** (Turing Complete: одна концепция за раз).
- **Идеал:**
  1. НЕ вводить очки/бейджи/левелы — это противоречит философии проекта (LEARNING_MODULE.md явно отвергает мотивационные тексты).
  2. Ввести Zachtronics-style гистограммы эффективности (стоимость решения, точность, время).
  3. Визуальная обратная связь при физически некорректных состояниях (КЗ, обрыв, перегрузка).

## Референсы красивых интерфейсов

[VISUAL-BUG] Severity: MEDIUM

- **Проект:** current-lab
- **Реальность/источники:** (knowledge)
  - **PhET CCK**: плоский дизайн, дружелюбная цветовая палитра (яркие цвета для компонентов, тёмный фон холста), крупные иконки, минимальный текст. Лампочка светится жёлтым — мгновенно читаемое состояние.
  - **SHENZHEN I/O / TIS-100**: тёмная тема, моноширинный шрифт, эстетика инженерного терминала/даташита. Солидер-паяльник-осциллограф как метафора.
  - **Falstad**: минималистичный, спартанский — холст и меню, всё внимание на схеме.
  - **current-lab сейчас**: ImGui-интерфейс (тёмный фон холста `IM_COL32(17, 22, 28, 255)`, MainWindow.cpp:70), функциональный, но утилитарный. Сетка, цветовое кодирование статуса слоёв.
  - **Проблема**: ImGui ограничивает визуальную эстетику — нет кастомных шейдеров, градиентов, анимаций свечения. Компоненты отрисованы как геометрические примитивы (линии, прямоугольники), нет «lifelike»-скина.
- **Идеал:**
  1. Кастомный рендерер компонентов с визуальным «характером»: лампочка с градиентом свечения (power/heat слой уже делает glow — можно усилить).
  2. Палитра компонентов с иконками вместо выпадающих списков.
  3. Цветовое кодирование состояния схемы: зелёный = норма, жёлтый = предупреждение, красный = ошибка/КЗ (status badge уже есть для слоёв, можно распространить на компоненты).

## Приоритетные рекомендации

1. **[P0] Drag-and-drop из палитры + lifelike-скин** — наибольший UX-разрыв с PhET.
2. **[P0] Визуальная обратная связь об ошибках** (КЗ, обрыв, перегрузка) — безопасность и обучение.
3. **[P1] Гистограммы эффективности** (Zachtronics-style) — intrinsic motivation без геймификации.
4. **[P1] Измерительные щупы на холсте** (вольтметр/амперметр) — практический навык.
5. **[P1] Галерея демо-схем** с описанием — onboarding.
6. **[P2] Scaffolded progression задач** — одна концепция за раз.
7. **[P2] Кастомный рендерер компонентов** с визуальным характером.
8. **[P3] AC-осциллограф** — когда появится AC-источник.
9. **[P3] Иерархические подсхемы** — для продвинутых.
10. **[P3] Итеративное тестирование со студентами** — валидация UX.
