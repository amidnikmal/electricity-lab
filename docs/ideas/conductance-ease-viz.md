# Идея (будущая задача): режим визуализации «проводимость = лёгкость»

Статус: **бэклог, не реализовано.** Добавлено по запросу пользователя 2026-06-15.

## Цель
Сделать ВИДИМЫМ один инвариант параллельных цепей:
- в параллели складываются **проводимости** (лёгкости), а не сопротивления;
- эквивалентное `R` параллельного куска **всегда меньше самой маленькой ветки**;
- добавление параллельной ветки **УВЕЛИЧИВАЕТ суммарный ток из источника**, а не перераспределяет фиксированный.

Бьёт прямо по школьной ошибке «параллельный резистор не меняет суммарный ток».

## Принцип
Физику НЕ пересчитывать. Брать из уже работающего MNA-решателя:
узловые потенциалы `V_i`, токи ветвей `I_k`, проводимости ветвей `G_k = 1/R_k`.
Визуализация — только слой отображения этих чисел.

## Маппинг величин (общий)
| Электрика | Метафора |
|-----------|----------|
| напряжение | перепад высоты / уклон |
| ток `I_k` | темп потока (в секунду) |
| `R` | узость канала |
| `G = 1/R` | ширина / сечение канала |
| параллель | каналы бок о бок, ширины складываются |
| последовательно | каналы в цепочку, узкий доминирует |

## Режим «Вода» (гидравлика)
- Узел = резервуар. Высота уровня ∝ потенциалу узла `V_i`. Разность высот между двумя узлами = напряжение на ветке. Источник = насос, держит перепад высот постоянным.
- Ветка-резистор = труба между резервуарами. Внутреннее сечение (видимая толщина) ∝ `G_k`. Тонкая = большое `R`, толстая = маленькое `R`.
- Ток = анимированный поток в трубе (частицы / объём в секунду), скорость ∝ `I_k`. Поток из высокого уровня в низкий.
- Параллель: трубы рядом между теми же двумя резервуарами. Показать, что суммарное сечение = сумма сечений. Эквивалентная одиночная труба ВИДИМО толще самой толстой из двух (`R_eq < min`).
- Последовательно: трубы торец-в-торец. Самая тонкая = бутылочное горло; эквивалентная труба тоньше самой тонкой.

## Режим «Механика» (шарики под гравитацией)
- Напряжение = перепад высоты / уклон (привод). Источник держит перепад постоянным и подаёт шарики сверху.
- Ветка = жёлоб, по которому скатываются шарики. Ширина (пропускная способность) ∝ `G_k`.
- Ток = шариков в секунду через жёлоб, ∝ `I_k`.
- Параллель = несколько желобов бок о бок между теми же уровнями: пропускные способности складываются, шариков в секунду суммарно больше.
- Последовательно = шарик проходит все сегменты по очереди; самый узкий задаёт темп.

## Главный UX-инвариант
- Когда пользователь вешает резистор параллельно существующему, анимация ОБЯЗАНА показать **рост суммарного расхода/тока из источника** (насос гонит больше воды в секунду; сверху сходит больше шариков), а не перетасовку фиксированного потока.
- Поверх параллельного куска всегда показывать `R_eq` и `G_eq` числом и подсвечивать, что `R_eq` меньше наименьшего `R` ветки.
- Перед показом результата добавления ветки **спросить у пользователя предсказание суммарного тока** (поле ввода), только потом запускать анимацию и сверить. Предсказание ДО симуляции, не после.
