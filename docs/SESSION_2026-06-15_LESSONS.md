## Что сделано (проверено, 566 тестов зелёные)
1. **Механизм offscreen-съёмки сцены в PNG** (`--capture`). Скрытое GLFW-окно + FBO →
   `buildDemo` → `LiveSim` → `ProjectionBuilder` → `drawPrimitives` → `glReadPixels` →
   `stb_image_write`. Файлы: `src/render/CaptureRenderer.*`, `src/app/CaptureConfig.h`,
   `src/stb_impl.cpp`, `src/third_party/stb_image_write.h`. → запушено в origin/main (T1).
2. **AC-демка починена.** Корень: `LiveSim` помечал цепь с `AcVoltageSource` как
   `settled`, когда выход выпрямителя выходил на стабильную пульсацию → сим засыпал →
   демка «не работала» (замирала). Фикс: цепь с AC НЕ усыпляется. + частота демки 50→2 Гц.
3. **Съёмка по сим-времени.** `--time` теперь = СИМУЛИРОВАННЫЕ секунды (гоним по
   `sim.time()` с фикс. шагом). Старый цикл считал РЕАЛЬНЫЕ секунды, авто-слоумо
   масштабировал их в почти неизменное `sim.time()` → разные `--time` давали
   идентичные (замёрзшие) кадры. Диагностировано по совпадению md5 двух кадров.

## Диагнозы (важно: ДВА бага оказались не тем, чем казались)
- **«Индуктор не связан с цепью» — НЕ баг солвера.** Все репро-тесты RL/RLC зелёные
  (ток растёт к V/R с τ, KCL держится). Это **визуал в механической аналогии**:
  маховик (`emitFlywheel`) рисуется гладким диском без зубьев, цепь «втыкается» в него
  без зацепления (в отличие от ведущей шестерни). Фикс — зубья на ободе. НЕ начато.
- **«Конденсатор-пружина зашкаливает» — конструкторская задача, НЕ быстрый фикс.**
  Угол вала пружины жёстко = `capTravel/pitchR`, и ВСЁ (цепные овалы, шестерни,
  кривошипы) фазо-синхронизировано через него. Тест `SpringCapacitor.NoGearTurnsOutOfSyncWithTheLoop`
  требует, чтобы все шестерни крутились с одной скоростью = скорости петли.
  Развязать амплитуду пружины от этой синхронизации, не сломав тест — реальная задача.
  Попытка агента (угол от мгновенного Vc) сломала 3 теста. НЕ начато.

## Зависания сборки — корень и рецепты (ГЛАВНОЕ)
Сеть к github на этой машине заблокирована → любой `FetchContent` git-clone виснет.

1. **НЕ убивать сборку (`pkill ninja/cmake`) посреди реконфигурации.** Это повреждает
   `build/_deps/<dep>-src` (напр. `nlohmann_json-src` исчез на полпути клона), после чего
   CMake пытается ПЕРЕКЛОНИРОВАТЬ его с github → вечный таймаут. Большая часть «зависаний»
   этой сессии — самонанесённые таким способом.
2. **Офлайн-сборка — правильный способ:** указать исходники депов явно:
   ```
   cmake -S . -B build \
     -DFETCHCONTENT_SOURCE_DIR_GLFW=<good>/glfw-src \
     -DFETCHCONTENT_SOURCE_DIR_NLOHMANN_JSON=<good>/nlohmann_json-src \
     -DFETCHCONTENT_SOURCE_DIR_BOX2D=<good>/box2d-src \
     -DFETCHCONTENT_SOURCE_DIR_IMGUI=<good>/imgui-src \
     -DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=<good>/googletest-src \
     -DFETCHCONTENT_SOURCE_DIR_GLM=<good>/glm-src
   ```
   `<good>` = `_deps` любой здоровой сборки. Проверено: configure exit 0, без сети.
3. **`FETCHCONTENT_FULLY_DISCONNECTED=ON` — НЕ использовать:** он пропускает
   `FetchContent_MakeAvailable`, и таргеты (`nlohmann_json::nlohmann_json`) не создаются
   → «target not found», генерация падает. Нужен `UPDATES_DISCONNECTED=ON` (пропускает
   только git-fetch) ИЛИ `SOURCE_DIR` (рецепт 2).
4. **Восстановление повреждённого `_deps`:** скопировать недостающий `<dep>-src` из
   здоровой сборки (`cp -r <good>/<dep>-src build/_deps/`), затем рецепт 2.
5. **Прокси для git** (если нужен реальный клон): `HTTP_PROXY=HTTPS_PROXY=http://127.0.0.1:2080`
   (тот же VPN-прокси, что для codex). Но рецепт 2 надёжнее (без сети вообще).
6. **GLOB `CONFIGURE_DEPENDS` для тестов** (в CMakeLists): при добавлении/удалении
   `tests/test_*.cpp` CMake делает реконфигурацию — это нормально, но небыстро.

## Засев нового worktree (для параллельных сборок)
Свежий worktree → его `cmake` повиснет на FetchContent. Перед работой: configure офлайн
рецептом 2, указав `SOURCE_DIR` на `_deps` здоровой сборки. Тогда `cmake --build` только
компилирует, без сети.
