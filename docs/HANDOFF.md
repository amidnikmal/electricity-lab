## ЧЕСТНОЕ ВРАЩЕНИЕ КОЛЁС: ОКНА МАХОВИКА + ШЕСТЕРНИ УЗЛОВ (2026-06-14) — 480 зелёных

Запрос пользователя: 4 окна на маховике источника ДЁРГАЛИСЬ и не вращались
честно вместе с колесом. + применить тот же приём к шестерням узлов.

ДИАГНОЗ (корень — мой предыдущий снап зацепления): грубая «намотка» бралась из
∫I·dt (componentIntegral·40/R), которая идёт в ~100 раз медленнее реальной
скорости цепи (сим: clamp(I·4000,±120)). Поэтому намотка k не накапливалась:
зубья периодичны (шаг зуба) и зацеплялись нормально, а ОКНА (шаг π/2, не кратный
шагу зуба) болтались в пределах одного зуба и прыгали при сбросе measMod — ровно
«дёрганье». То же у шестерён узлов (фаза от nodeIntegral, тоже ∫|I|·dt).

ФИКС:
- **Честный ход цепи прокинут в рендер**: MainWindow интегрирует
  m_chainTravel[comp] += spec.targetSpeed·dt (ТА ЖЕ величина, что двигает ролики
  сима — loop.phase), кладёт в ViewParams.chainTravel (через CircuitCanvas
  setChainTravel, как chainLinks/flowIntegrals).
- **emitSprocket теперь две фазы**: toothPhase (зубья, снап к роликам) и
  bodyPhase (тело: ступица/окна/рукоятка — крутится по честному ходу, гладко).
- **emitCrank/emitGears**: bodyPhase = sourceDriveSprocketPhaseFromChainTravel(
  chainTravel, R) = −travel/R (гладко, верная скорость, с учётом клампа); зубья
  снапятся к измеренным роликам (wheelMeshPhase), k от bodyPhase теперь
  накапливается верно (bodyPhase и ролики идут с ОДНОЙ скоростью −targetSpeed/R).
- **wheelMeshPhase** (обобщённый, заменил sourceSprocketMeshPhase): взвешенное
  круговое среднее на частоте зубьев со СГЛАЖЕННЫМ радиальным окном (вес 1 на
  питч-окружности → 0 на band=2·rollerR) — ролики плавно входят/выходят на концах
  дуги, без скачков мембершипа (это убирало остатки дёрганья). compId<0 = любой.
- **Шестерни узлов**: bodyPhase = −travel доминирующей входящей ветки / R (цепь
  огибает узел по часовой при +ходе → минус); зубья снапятся к роликам ИМЕННО
  доминирующей ветки (bestComp), т.к. независимые посим-ветки не сфазировать —
  одну зацепляем чисто. Окна узловых шестерён рисуются только при rootR>6 (на
  дефолтной толщине узлы мелкие → окон нет, но вращение/зацепление честные).
- Fallback на ∫I·dt-фазу сохранён, когда chainTravel не прокинут (юнит-тесты).
- Тесты: DriveSprocketHolesSpinAtHonestChainSpeed (окна крутятся на −Δtravel/R,
  no-slip), DriveSprocketTeethMeshIntoChainRollerGaps (зубья в зазорах, держится

## ЗУБЬЯ МАХОВИКА-ИСТОЧНИКА ЗАЦЕПЛЕНЫ С ЦЕПЬЮ (2026-06-14) — 479 тестов зелёные

Запрос пользователя: маховик источника должен быть ВИЗУАЛЬНО ЗАВЯЗАН на цепь —
зубья сидят в зазорах между роликами и толкают цепь (без проскальзывания), а не
крутятся сами по себе.

ДИАГНОЗ: сим двигает ролики цепи со скоростью clamp(I*4000, ±120) (насыщается на
120 path-u/s), а зубья звёздочки в emitCrank крутились от ∫I·dt·40/R — в ~100 раз
медленнее. Зубья почти стояли, цепь проносилась мимо: никакого зацепления.

ФИКС (src/projection/ProjectionBuilder.cpp):
- `sourceSprocketMeshPhase()` — измеряет угловое положение роликов, реально
  сидящих на питч-окружности маховика (|r−pitchR|<2.5·rollerR), круговым средним
  на ЧАСТОТЕ ЗУБЬЕВ (atan2(Σsin(teeth·θ), Σcos(teeth·θ))/teeth) → фаза по модулю
  шага зуба; зубья ставятся +полшага (в зазоры между роликами).
- emitCrank: travel-фаза (∫I·dt) остаётся непрерывной «намоткой» (плавные
  ступица/окна/рукоятка, верное направление), а измеренное зацепление СНАПИТ её
  на зазоры: angle0 = meshMod + round((angle0−meshMod)/toothPitch)·toothPitch.
  Оба меняются непрерывно → итог непрерывен И зацеплен. Зубья теперь движутся
  ВМЕСТЕ с роликами (no-slip автоматически, т.к. привязаны к реальным роликам).
- Применено ТОЛЬКО к источнику (emitCrank). Тот же рассинхрон есть у шестерён
  узлов (emitGears: nodeIntegral vs сим-цепь) — НЕ трогал, пользователь просил
  про маховик источника; кандидат на тот же фикс при желании.
- Тест MechanicsChain.DriveSprocketTeethMeshIntoChainRollerGaps: каждый ролик на
  питч-окружности дальше 0.30·toothPitch от любого зуба (в зазоре), проверка в
  двух положениях движущейся цепи (зацепление держится при движении).
- Визуально глазами пользователем ещё не подтверждено.

**Мембранный конденсатор (коммит 5d8d6c7):** emitTank переписан с полоски-уровня
на БАК С УПРУГОЙ МЕМБРАНОЙ. Обе камеры всегда полны водяными шариками (вода
несжимаема), мембрана — выгнутая полилиния, прогиб ∝ Vc (знаковый); шарики СКВОЗЬ
не проходят (= «C блокирует ток»), A-сторона подкрашивается «заряженной» ∝ |Vc|
(растущая область = наполнение). Бак шире щели схемы — движение мембраны видно.
Ток через C = скорость мембраны: заряжен → встала → поток ноль. Тест
HydraulicProjection.CapacitorTankFillsAndMembraneRespondsToCharge.

**RLC звенит (коммит d59e1cd):** две причины, почему звона не было:
1. Передемпфирование ПРОВОДАМИ (распределённая модель, 0.5 Ом/ед.; длинные
   замыкающие провода → ~360 Ом → Q≈0.08). Фикс: RLC-демо перестроено в петлю из
   4 элементов БЕЗ проводов (источник/R/L/C по сторонам прямоугольника), R=4 Ом → Q≈8.
2. Авто-замедление по крошечному R*C (мс) << периода звона (~0.2 с) → скорость
   ~1%, звон полз. Фикс: LiveSim::oscillationTimescale() = 2π√(LC) по значениям L,C
   (у последовательного RLC тевенин катушки не находит DC-путь — C рвёт, потому по
   значениям; требуем подключённый C + наличие L). onCircuitEvent: storyTau =
   max(наименьшая tau, период звона). RC/RL не затронуты. Тесты:
   OscillatoryRlcSlowsToTheRingPeriodNotTheTinyRc, NonOscillatoryRcHasNoRingTimescale.

### КОРЕНЬ (подтверждён чтением кода)
Две НЕЗАВИСИМЫЕ геометрии резистора в Water-виде:

## Project overview

Интерактивное обучающее приложение для электрических цепей: единая `CircuitModel`, MNA-солвер (DC + transient), три честные проекции одной модели (Circuit / Physics / Mechanics), обучающий модуль на science of learning с AI-resilience предохранителями в коде.

## Architecture (после рефакторинга)

```text
CircuitModel (src/circuit/Circuit.h, single source of truth, stable ComponentId)
  -> CircuitSolver (src/solver/) : DC | stepTransient (companion BE/Trapezoidal) | solveTransientSnapshot
       diode states: solveIterative (ideal PWL fixed point)
  -> ProjectionBuilder (src/projection/) : ЕДИНСТВЕННЫЙ источник render-данных
       ProjectionKind::{Schematic, Physics, Mechanics} -> ProjectionResult{RenderPrimitives, ElementState[]}
       ElementGeometry.h (символы C/L), MechanicsMapping.h (аналогия, P=V*I сохраняется точно)
  -> PrimitiveRenderer (src/render/) : тупой ImGui-бэкенд; RenderPrimitives/ColorMaps — pure data
  -> CanvasInteraction (src/ui/) : edit/hit-test, потребляет InteractionInput (без ImGui, тестируемо)
  -> CircuitCanvas (src/ui/) : тонкая оболочка (камера + клок анимации + сборка ViewParams)
  -> MainWindow : layout Single/Dual/Triple, transient-контролы, DualViewState (3 камеры, sync)
Learning: src/learning/ (TaskGenerator: ground truth из солвера; LearningSession: предохранители 1-6 КОДОМ;
          Lessons.h: арка вывода; AnkiExport: AnkiConnect addNotes, FSRS на стороне Anki)
Assistant: src/assistant/LlmClient.* (OpenAI-compatible, llama.cpp/vLLM/API; критик-не-решатель)
Net: src/net/HttpClient.* (POSIX, plain HTTP, localhost-сервисы)
```

Инвариант: один элемент модели = один ComponentId = N проекций из одной модели+solution. Никаких коллекций элементов на проекцию. Editing/selection/camera — через общую модель и DualViewState.

## Known limitations / Recommended next pass

- Нет AC-источника (синус) — без него диод не показывает выпрямление периодического сигнала; добавить `ComponentType::AcVoltageSource` (амплитуда+частота, MNA RHS = f(t) в transient).
- Diode: только идеальная модель; Shockley (Ньютон) — отдельным флагом.
- LLM-вызов блокирующий (UI замирает на время запроса) — вынести в поток.
- extractAssistantReply — таргетный парсер, \uXXXX -> '?'; при желании заменить мини-JSON-парсером.
- HttpClient — plain HTTP (для https нужен локальный прокси); сознательное решение для портативности.
- Учебная панель не навязывает FSRS-расписание tool-free сессий внутри приложения — расписание у Anki.

- Приложение визуально не прогонялось в этом проходе (headless-сессия): сборка и 240 тестов зелёные, но стоит запустить `DISPLAY=:0 ./build/current-lab` и глазами проверить triple-layout, transient-анимацию C/L, mechanics-вид, Learning-панель.
