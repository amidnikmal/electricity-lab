# Галерея аналогий — офлайн-ревизия сцен (2026-06-16)

Офлайн-рендер КАЖДОЙ сцены правой панели ЭМ-режима в PNG (чистая физика +
цвет, без ImGui/GL) — чтобы глазами проверить «детский тест» из
`docs/EM_ANALOGY_SPEC_2026-06-16.md` и подобрать параметры, при которых
картинка очевидна ребёнку 7-10 лет за 10 секунд.

- Инструмент: `tools/analogy_gallery.cpp`
  (`g++ -std=c++20 -O2 -I src tools/analogy_gallery.cpp -o /tmp/gallery && /tmp/gallery`).
- Картинки: `docs/em-gallery/*.png` (апскейл ×4, nearest).
- Цвет — ТОЧНО как `EmPanel::waterColor`: знаковая высота t∈[-1,1] →
  deep(10,26,64)/mid(34,102,168)/foam(222,244,255), нормировка по 95-му
  перцентилю |height| (для двух щелей — по области за барьером).
- Геометрия в инструменте: ось `j` (столбец) идёт ВПРАВО (вдоль потока волны),
  ось `i` (строка) — ВНИЗ. Источник плоской волны/щелей/преломления стоит у
  левого края (малые `j`). В реальной панели координаты те же, что в
  `configureAnalogy` — отличается лишь то, что я НЕ накладываю ImGui-подсказки,
  кроме грубой подрисовки стен/границы прямо в пиксели.

ВАЖНО: я НЕ трогал `src/`. Все числа ниже — рекомендации к ручной вставке в
`EmPanel::configureAnalogy` (и для волновода — слегка в `drawWaterPane`).

## 1. Диполь (`DipoleRadiator`) — «Брось камень — побегут круги»

**Базовая версия читается идеально.** `01_dipole_base.png`: ровные
концентрические круги из одной точки в центре, источник насыщен перцентильной
нормировкой и не «съедает» рябь. Детский тест «где упал камень?» → центр —
проходит мгновенно.

**Рекомендация:** оставить как есть.
```cpp
m_ripple->addDrivenSource(N / 2, N / 2, 0.06, 1.0);   // без изменений
```

---

## 2. Плоская волна (`PlaneWave`) — «Волны бегут ровными рядами»

Ряды по сути ВЕРТИКАЛЬНЫЕ и параллельные — направление «вправо» читается.
В базовой версии (`02_plane_base.png`, 360 шагов) полосы слегка «выгибаются» у
дальнего края: набегает несовершенство поглощающей границы Мура за долгий
прогон. На `02_plane_f05_s220.png` (тот же источник, но меньше шагов, фронт ещё
не дошёл до правого края) полосы — идеально прямые, а движущийся фронт делает
направление ещё очевиднее.

В живой панели волна идёт непрерывно, поэтому фронт всё равно заполнит экран;
«выгиб» — косметика границы, а не ошибка параметров. Сами ряды прямые.

**Вердикт:** читается. **Рекомендация:** параметры менять НЕ обязательно —
оставить `f=0.05`, источник в строке 3. Полосы прямые; правка не нужна.
```cpp
for (int i = 1; i < N - 1; ++i) m_ripple->addDrivenSource(i, 3, 0.05, 1.0);  // без изменений
```
(Опционально, если захочется идеально прямых рядов и в статике — слегка снизить
частоту до `0.045`, см. `02_plane_f045.png`: ряды чуть шире и устойчивее.)

## 3. Две щели (`DoubleSlit`) — «Две волны: где встретились — горбик»

База (`03_slit_base.png`) читается: стенка видна, две щели видны, за стенкой —
веер. Но при `sep=13` лепестки интерференции тесноваты и контраст «тихо/плещет»
бледный — это самая важная сцена, её надо сделать очевидной.

**Подбор:** развёл щели сильнее и сузил их.
- `03_slit_sep16.png` (`sep=16, half=2`) — ЛУЧШИЙ: за стенкой чёткий веер
  ярких лучей-дорожек, разделённых тёмными «спокойными коридорами». Ровно то,
  что спрашивает детский тест «где спокойно — где плещет».
- `03_slit_sep11.png` — лепестков мало, центральный слишком широкий.
- `03_slit_f05.png` — лопасти жирнее, полос меньше, грубее.

**Вердикт:** чиню — развожу щели. Финал:
```cpp
for (int i = 1; i < N - 1; ++i) m_ripple->addDrivenSource(i, 6, 0.06, 1.0);
const int jb = static_cast<int>(N * 0.42);   // стенка (можно 0.40 — чуть больше места справа)
const int c = N / 2, sep = 16, half = 2;     // было sep=13, half=3 → развести и сузить щели
for (int i = 0; i < N; ++i) {
    bool slitA = std::abs(i - (c - sep)) <= half;
    bool slitB = std::abs(i - (c + sep)) <= half;
    if (!slitA && !slitB) m_ripple->setBarrier(i, jb, true);
}
```
ВАЖНО: те же `sep` и `half` нужно поправить и в `drawWaterPane`
(подрисовка стены/щелей) — иначе ImGui-подсказка разъедется с физикой.

## 4. Преломление (`DielectricInterface`) — «На мелком волны медленнее и теснее»

**Читается сразу.** `04_refract_base.png`: правая половина («мелко», speed=0.5)
явно несёт более частые и короткие гребни, чем левая; граница по центру видна.
Детский тест «с какой стороны волны теснее?» → справа — проходит. Левую половину
слегка «рябит» от отражения на границе, но ключевой контраст «справа теснее»
однозначен.

**Рекомендация:** оставить как есть.
```cpp
for (int i = 1; i < N - 1; ++i) m_ripple->addDrivenSource(i, 3, 0.05, 1.0);
for (int i = 0; i < N; ++i)
    for (int j = N / 2; j < N; ++j) m_ripple->setSpeedScale(i, j, 0.5f);   // без изменений
```
(Если хочется убрать рябь слева — можно поднять speed медленной зоны до `0.6f`:
контраст «теснее» останется, отражение от границы ослабнет. Не обязательно.)

## 5. Волновод (`Waveguide`) — «В канавке волна не разбегается»

База (`05_waveguide_base.png`, `halfCh=10, f=0.07`): главный контраст «внутри
плещет — снаружи штиль» ЕСТЬ и читается (детский тест «волна вышла за стенки?» →
нет). Но канал узкий (20 ячеек) и при `f=0.07` содержимое выглядит как цепочка
«бусин», а не «ровные гребни, бегущие вдоль канала».

**Подбор:** шире канал + ниже частота.
- `05_wg_w16_f04.png` (`halfCh=16, f=0.04`) — ЛУЧШИЙ: чёткие чередующиеся
  светлые/тёмные ПОЛОСЫ во всю ширину канала, идущие до дальнего конца; снаружи
  идеально гладкая синева. Читается и «не разбегается», и «бежит вдоль канала».
- `05_wg_w14_f05.png` — лучше базы, но полосы ещё узковаты.

**Вердикт:** чиню — расширяю канал, понижаю частоту. Финал:
```cpp
const int c = N / 2, halfCh = 16;            // было 10 → шире канал, видны гребни
for (int j = 0; j < N; ++j) {
    m_ripple->setBarrier(c - halfCh, j, true);
    m_ripple->setBarrier(c + halfCh, j, true);
}
m_ripple->addDrivenSource(c, 4, 0.04, 1.0);  // было (c,6,0.07): ниже f, источник ближе к краю
```
ВАЖНО: `halfCh` поправить и в `drawWaterPane` (две стенки канала рисуются по
`halfCh`).

## 6. Верёвка / зеркало (`Mirror`) — «Волна вернулась — верёвка прыгает на месте»

**ГЛАВНАЯ ПОЧИНКА.** База (`06_rope_base.png`, `n=220, f=0.05`) — **провал
детского теста**: огибающая почти плоская, узлов НЕ видно, картинка читается как
обычная бегущая волна, а не стоячая. Причина — частота не резонансная и слишком
высокая для струны: число полуволн ≈ `4·L·f = 4·219·0.05 ≈ 44`. Узлы стоят через
~5 пикселей — глазом не различить, стоячая структура смазана.

**Подбор резонанса.** Для закреплённой струны (FarEnd::Fixed) резонанс
`f_m = m·c/(2L)`, c=0.5. Для `n=160` (L=159): `f_m = m·0.001572`. Цель — 4-6
пучностей, чтобы узлы были крупными и считаемыми:
- `06_rope_f4.png` (`f≈0.00629`, m=4) — чисто, 4 пучности.
- `06_rope_f5.png` (`f≈0.00786`, m=5) — ОТЛИЧНО: 5 пучностей, 4 узла, читается
  как учебник.
- `06_rope_f6.png` (`f≈0.00943`, m=6) — тоже отлично: 5 жёлтых узлов ровно по
  пинч-точкам огибающей, спинделя крупные и чёткие.

Во всех трёх огибающая (пунктир) образует веретёна-пучности, а жёлтые метки
узлов стоят точно в перетяжках, где верёвка не движется. Детский тест «покажи
точку, которая не двигается» → ткнуть в жёлтую метку — проходит безупречно.

**Вердикт:** чиню — резонансная частота + короче струна. Рекомендованный финал
(`f5`, баланс «узлов достаточно / не тесно»):
```cpp
m_string = std::make_unique<StringWave>(160);   // было 220 — узлы крупнее на пиксель
m_string->setDrive(0.00786, 1.0);               // было 0.05 — РЕЗОНАНС m=5 (f_m=m*c/(2L))
m_string->setFarEnd(StringWave::FarEnd::Fixed);
m_ropeEnv.assign(160, 0.0f);
```
Альтернатива `f6` (0.00943) — если хочется на один узел больше.

Замечания по `drawRopePane`:
- При резонансной частоте огибающая `m_ropeEnv` корректно проявит узлы
  (перетяжки около нуля) — порог детектора узлов `< 0.18f` подходит.
- Стоит дать огибающей время устояться: после смены сцены первые ~несколько
  периодов (T=1/f≈127 шагов) узлы ещё «гуляют». В офлайн-рендере я делал
  warmup ~5000 шагов; в живой панели это набежит за пару секунд проигрывания —
  отдельной правки не требует, но при «Сброс» узлы появятся не мгновенно.
- Уберите/игнорируйте ложную метку узла у самой «руки» (i≈3): около драйва
  огибающая мала не из-за узла. Можно начинать детектор узлов с `i > 6`.
